An atomic machine for verified concurrent compilation

UIC · 2026–present

MS thesis with Prof. William Mansky · Rocq, Verified Software Toolchain (VST)

Concurrent separation logic guarantees that a verified program never gets stuck; verified concurrent compilers like CASCompCert need a different guarantee, data-race freedom. I'm building the bridge: a language-generic "atomic machine" semantics in Rocq that turns one into the other.

  • ~4,600 lines of Rocq, ~190 lemmas. Instantiated for a port of RustBelt's λRust, with an equivalence theorem showing a program is safe on the atomic machine iff it is safe in the reference semantics — and a counterexample showing why a naive forward simulation doesn't suffice.
  • Merged upstream into Princeton's VST: #859 "Atomic machine", #856 build-dependency fix, plus follow-up work on the vst_on_iris branch.

rocq_llm_bench: AI agents vs. machine-checked proofs

Sept 2026 · Python, Rocq, Nix

A reproducible benchmark that runs AI coding agents — Claude Code, Codex, Cursor, pi, Google's agy — on theorem proving in Rocq, from textbook lemmas to Putnam 2025, and measures where the wall-clock time actually goes.

  • A verifier that can't be fooled: the original theorem statement is re-checked against the agent's proof in a separate file, so redefined notation doesn't help, and Print Assumptions must bottom out in the standard library.
  • Identical sandbox for every harness: bubblewrap + network namespace + a TLS-terminating proxy that strips server-side web search and logs exact per-call timing and token cost.
  • It caught cheating. Agents copied published Putnam solutions from the web, mined reference proofs out of git log, and found them in a Nix store snapshot. Each hole was closed and the affected runs redone.
  • Findings: several frontier agents now solve all 9 formalized Putnam 2025 problems within an hour, typically in a few minutes each; the prover is only 0–11% of wall time — inference dominates. I also found three false or vacuous statements in miniF2F-rocq's IMO set.

Verified Unicode normalization in Lean 4

Summer 2026 · Lean 4

A streaming NFC/NFD/NFKC/NFKD normalizer for Unicode 17 with machine-checked proofs, then used as a differential-testing oracle against about ten widely used implementations.

  • 287 theorems, no sorry: outputs are normalized, normalization is idempotent, all 16 composition identities between forms, incremental = batch, and productivity on infinite stream-safe input.
  • Passes 100% of the 20,034 official conformance rows; ~24.5M differential normalizations.
  • Found real bugs in other libraries, including composition bugs in Go's golang.org/x/text. Upstream reports in progress.

Root-causing a GPU hang, from PyTorch to firmware

Sept 2026 · ROCm, Linux amdgpu

Training on my laptop's Radeon 760M (gfx1103) intermittently reset the GPU. I traced it through PyTorch, the ROCm runtime, and the kernel driver to the preemption mechanism: the default software context-save trap can't preempt waves parked at a barrier, and the driver's own restore path has one, so an eviction landing just after a restore deadlocked until a timeout reset the GPU.

  • A driver patch switching to hardware traps survived ~73k saved-wave evictions and 13.5k training steps with no faults and no throughput loss — contradicting an upstream assumption about this chip family. Upstream report in preparation.
  • On the way: ROCm is 4.1× faster than the CPU in BF16 for a large dense network on this iGPU.

Fuzzing a Zen 4 CPU with sandsifter

Aug 2026 · Python, C, x86

Ported the sandsifter x86 instruction fuzzer to Python 3 (fixing a bug that silently corrupted every logged byte ≥ 0x80), ran 822M instructions on a Ryzen 5 7640U, and traced all 19.3M reported anomalies to about ten root causes, each confirmed with a small C test program.

  • An AMD decoder quirk: the CPU fetches two extra bytes before rejecting 0F 78, so at a page boundary it page-faults where Intel raises #UD.
  • A VEX encoding the manual forbids that executes anyway; 66 0F 8x jumps truncating RIP to 16 bits; Linux's UMIP emulation making gdb's stepi silently skip an instruction; several disassembler (Capstone) bugs.

Depthwise Sobolev preconditioning for ResNets

in progress · PyTorch

Treating a ResNet as a discretized ODE in depth and preconditioning updates by depth frequency. Hessian spectroscopy so far: at initialization the curvature is flat across depth frequencies, and predicted stability limits track the measured top Hessian eigenvalues (within ~12%) across depths 16–256 — which overturned my starting hypothesis.
