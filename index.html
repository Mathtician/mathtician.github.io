An atomic machine for verified concurrent compilationMS thesis · UIC · 2026 to present Rocq semantics bridging concurrent separation logic and verified concurrent compilers. Merged into Princeton's VST.

Advised by Prof. William Mansky · Rocq, Verified Software Toolchain (VST)

Concurrent separation logic guarantees that a verified program never gets stuck. Verified concurrent compilers like CASCompCert need a different guarantee: data-race freedom. I'm building the bridge, a language-generic "atomic machine" semantics in Rocq that turns one into the other.

  • ~4,600 lines of Rocq, ~190 lemmas. Instantiated for a port of RustBelt's λRust, with an equivalence theorem (a program is safe on the atomic machine iff it is safe in the reference semantics) and a counterexample showing why a naive forward simulation doesn't suffice.
  • Merged upstream: VST #859 "Atomic machine" and #856 (build dependencies), plus follow-up work on the vst_on_iris branch.

LLMs and machine learning

rocq_llm_bench: AI agents vs. machine-checked proofsSept 2026 · Python, Rocq, Nix

824 graded attempts by 27 agent configurations (Claude Code, Codex, Cursor, pi, agy) on 108 Rocq problems, from textbook lemmas to Putnam 2025: 60 hours of agents proving theorems.

How it works and what it found
  • A verifier that can't be fooled: the original theorem statement is re-checked against the agent's proof in a separate file, so redefined notation doesn't help, and Print Assumptions must bottom out in the standard library.
  • Identical sandbox for every harness: bubblewrap, a network namespace, and a TLS-terminating proxy that strips server-side web search and logs exact per-call timing and token cost.
  • It caught cheating. Agents copied published Putnam solutions from the web, mined reference proofs out of git log, and found them in a Nix store snapshot. Each hole was closed and the affected runs redone.
  • Findings: several frontier agents solve all 9 formalized Putnam 2025 problems within an hour, typically in a few minutes each, and the prover is only 0 to 11% of wall time; inference dominates. I also found three false or vacuous statements in miniF2F-rocq's IMO set.

Depthwise Sobolev preconditioning for ResNetsin progress · PyTorch Treating depth as time and preconditioning by depth frequency; Hessian spectroscopy overturned my starting hypothesis.

A ResNet is a discretized ODE in depth, so updates can be preconditioned by their frequency along depth. At initialization the curvature turns out to be flat across depth frequencies, and the predicted stability limits track the measured top Hessian eigenvalues (within ~12%) across depths 16 to 256.

Root-causing a GPU hang, from PyTorch to firmwareSept 2026 · ROCm, Linux amdgpu Traced intermittent GPU resets to a preemption deadlock and validated a driver fix over ~73k evictions.

Training on my laptop's Radeon 760M (gfx1103) intermittently reset the GPU. I traced it through PyTorch, the ROCm runtime, and the kernel driver to the preemption mechanism. The default software context-save trap can't preempt waves parked at a barrier, and the driver's own restore path has one, so an eviction landing just after a restore deadlocked until a timeout reset the GPU.

  • A driver patch switching to hardware traps survived ~73k saved-wave evictions and 13.5k training steps with no faults and no throughput loss, contradicting an upstream assumption about this chip family. Upstream report in preparation.
  • Along the way: ROCm is 4.1× faster than the CPU in BF16 for a large dense network on this iGPU.
Fuzzing a Zen 4 CPU with sandsifterAug 2026 · Python, C, x86 822M instructions on a Ryzen 7640U; all 19.3M anomalies traced to ~10 root causes.

Ported the sandsifter x86 instruction fuzzer to Python 3 (fixing a bug that silently corrupted every logged byte ≥ 0x80), ran it on a Ryzen 5 7640U, and confirmed each root cause with a small C test program.

  • An AMD decoder quirk: the CPU fetches two extra bytes before rejecting 0F 78, so at a page boundary it page-faults where Intel raises #UD.
  • A VEX encoding the manual forbids that executes anyway; 66 0F 8x jumps truncating RIP to 16 bits; Linux's UMIP emulation making gdb's stepi silently skip an instruction; several Capstone disassembler bugs.
